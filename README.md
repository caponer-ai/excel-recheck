# excel-recheck

Незалежний перерахунок підсумків Excel-звіту. Інструмент бере звіт, сам рахує кожен підсумок з деталей і порівнює з тим, що стоїть у файлі. Результат має три блоки: що зійшлось, що не перевірено і чому, звідки взято кожне число.

Зроблено для ситуації, коли звіт або таблицю готує AI-агент чи людина, а помилка в сумі коштує грошей. Правдоподібний результат і перевірений результат це різні речі, і звіт має показувати, де який.

## Що він робить

- Перевіряє рівності виду «підсумок = сума доданків мінус від'ємники», у межах аркуша і між аркушами.
- Розбирає таблицю з групами: для кожного рядка перевіряє рух (початок + прихід − розхід = кінець), для кожної групи і для рядка «Разом» перевіряє, що підсумок дорівнює сумі рядків-деталей.
- Рахує гроші в `Decimal`. Розбіжність в одну копійку це розбіжність, а шум від `float` нею не стає.
- Ніколи не перетворює нечислове на нуль. Число, набране текстом, текст посеред суми, порожній підсумок, формула без збереженого значення дають статус «не перевірено» з адресою клітинки і причиною.
- Показує числа, яких не торкнулась жодна перевірка, і рядки таблиці, які не підійшли під жодне правило. Звіт не вдає, що перевірив усе.
- Для кожної перевірки пише адреси клітинок: що з чим порівнювали.

Код виходу: `0` усе зійшлось, `1` є розбіжності, `2` розбіжностей немає, але щось не перевірено, `3` файл або правила не читаються.

## Спробувати

```
pip install -r requirements.txt
python -m recheck demo/with_defects.xlsx --checks demo/checks.json --out report.md
```

Готовий зразок звіту лежить у [demo/report_with_defects.md](demo/report_with_defects.md), його можна прочитати без запуску. Тест перевіряє, що цей файл збігається з тим, що генерує код.

## Демо: п'ять підкладених помилок

Дані в `demo/` вигадані, їх генерує `demo/make_demo.py`. У файл `with_defects.xlsx` підкладено п'ять помилок. Кожна має тест: помилка мусить змінити статус рівно тих перевірок, які записані в реєстрі, і жодної іншої.

| № | Помилка | Що має статися |
|---|---|---|
| D1 | «Всього» у зведенні загубило один доданок | 2 розбіжності |
| D2 | Сума статті набрана текстом: «8 500 805,74» | 1 перевірка «не перевірено», а не «зійшлось» |
| D3 | Переставлені сусідні цифри в залишку рядка | 3 розбіжності: рядок, група, загальний підсумок |
| D4 | Підсумок більший за суму статей на 0,01 | 1 розбіжність; перевірка в тисячах з допуском її не бачить |
| D5 | «Разом» містить ще й підсумок групи | 2 розбіжності |

На чистому файлі всі 40 перевірок сходяться без жодного зауваження. З чисел у файлі 111, перевірками покрито 95, а 16 (стовпчик «Минулий рік») навмисно лишено без правил, щоб було видно, як виглядає блок «не перевірено».

## Як перевірено сам інструмент

Усі числа нижче отримано 20.11.2026 на одному ноутбуці (Windows 11, Python 3.12.6).

- `pytest`: 42 тести, усі зелені.
- Тести і код писались разом, тому зелений прогін сам нічого не доводить. `python tools/mutants.py` по черзі вносить у код 15 навмисних поломок (наприклад, «текст у сумі мовчки пропускається» або «допуск розширено на копійку») і перевіряє, що тести падають. Спіймано 15 з 15. Поломки придумував той самий автор, що й тести, тож це нижня планка, а не доказ повноти.
- Один прогін на демо-файлі займає 0,02 с (один замір, час друкується в консолі при кожному запуску).

## Звідки метод

Метод узято з двох реальних перевірок фінансових звітів у липні 2026 року. У першій 77 підсумків квартального звіту перераховано з деталізованих рядків: 75 зійшлись копійка в копійку, а дві розбіжності виявились помилкою в самому шаблоні звіту, де рядок «Всього» губив один доданок. У другій оборотну відомість складу розібрано до рядків: сума деталей мала дорівнювати підсумку файлу.

Ті файли і скрипти приватні. Тут метод перенесено на вигадані дані і переписано так, щоб правила перевірки жили в окремому файлі, а не в коді.

## Чого тут немає

- Читає лише `.xlsx`. Старий `.xls` треба спершу перезберегти.
- Правила пише людина. Інструмент не здогадується, які клітинки є підсумками.
- Об'єднані клітинки читаються як порожні. Формула, яку Excel не перерахував перед збереженням, дає «не перевірено».
- Перевіряється арифметика і цілісність звіту, а не зміст. Якщо сума порахована правильно з неправильних первинних даних, інструмент цього не побачить.
- Кількості в різних одиницях (штуки, літри, упаковки) не сумуються і не перевіряються.
- Скільки часу це економить порівняно з ручною звіркою, не заміряно: для цього треба засікти, скільки та сама звірка займає в людини.
