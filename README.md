# excel-recheck

[![tests](https://github.com/caponer-ai/excel-recheck/actions/workflows/tests.yml/badge.svg)](https://github.com/caponer-ai/excel-recheck/actions/workflows/tests.yml)

Незалежний перерахунок підсумків Excel-звіту. Інструмент бере звіт, сам рахує кожен підсумок з деталей і порівнює з тим, що стоїть у файлі. Результат має три блоки: що зійшлось, що не перевірено і чому, звідки взято кожне число.

Другий режим звіряє два документи рядок за рядком: акт, який підготував агент, проти еталонного акта, зробленого людиною (розділ «Звірка акта з еталоном» нижче).

Зроблено для ситуації, коли звіт або таблицю готує AI-агент чи людина, а помилка в сумі коштує грошей. Правдоподібний результат і перевірений результат це різні речі, і звіт має показувати, де який.

## Що він робить

- Перевіряє рівності виду «підсумок = сума доданків мінус від'ємники», у межах аркуша і між аркушами.
- Розбирає таблицю з групами: для кожного рядка перевіряє рух (початок + прихід − розхід = кінець), для кожної групи і для рядка «Разом» перевіряє, що підсумок дорівнює сумі рядків-деталей.
- Рахує гроші в `Decimal`. Розбіжність в одну копійку це розбіжність, а шум від `float` нею не стає.
- Ніколи не перетворює текст на нуль. Число, набране текстом, текст посеред суми, порожній підсумок, формула без збереженого значення дають статус «не перевірено» з адресою клітинки і причиною.
- Порожній доданок рахує як нуль, але кожну таку клітинку перелічує у звіті окремим блоком.
- Показує числа, яких не торкнулась жодна перевірка, і рядки таблиці, які не вкладаються в правила: рядок без коду, рядок із чужим кодом усередині групи, рядки після «Разом». Звіт не вдає, що перевірив усе.
- Відхиляє правила, які вимикають перевірку: нескінченний або від'ємний допуск, нульовий множник, підсумок серед власних доданків, цифра замість літери стовпчика.
- Допуск, не менший за самі числа, які порівнюються, дає «не перевірено»: з ним зійшлося б що завгодно.
- Для кожної перевірки пише адреси клітинок: що з чим порівнювали.

Код виходу: `0` усе зійшлось, `1` є розбіжності, `2` розбіжностей немає, але щось не перевірено або рядки не вкладаються в правила, `3` файл або правила не читаються, або звіт не вдалося записати. Порожній доданок, порахований як нуль, код виходу не змінює: він лише перелічений у звіті.

## Спробувати

```
pip install -r requirements.txt
python -m recheck demo/with_defects.xlsx --checks demo/checks.json --out report.md
```

Готовий зразок звіту лежить у [demo/report_with_defects.md](demo/report_with_defects.md), його можна прочитати без запуску. Тест перевіряє, що цей файл збігається з тим, що генерує код.

## Демо: п'ять підкладених помилок

Дані в `demo/` вигадані, їх генерує `demo/make_demo.py`. У файл `with_defects.xlsx` підкладено п'ять помилок. Кожна має тест: помилка мусить змінити статус рівно тих перевірок, які записані в реєстрі, і жодної іншої.

| № | Помилка | Що має статися |
|---|---|---|
| D1 | «Всього» у зведенні загубило один доданок | 2 розбіжності |
| D2 | Сума статті набрана текстом: «8 500 805,74» | 1 перевірка «не перевірено», а не «зійшлось» |
| D3 | Переставлені сусідні цифри в залишку рядка | 3 розбіжності: рядок, група, загальний підсумок |
| D4 | Підсумок більший за суму статей на 0,01 | 1 розбіжність; перевірка в тисячах з допуском її не бачить |
| D5 | «Разом» містить ще й підсумок групи | 2 розбіжності |

На чистому файлі всі 40 перевірок сходяться без жодного зауваження. З чисел у файлі 111, перевірками покрито 95, а 16 (стовпчик «Минулий рік») навмисно лишено без правил, щоб було видно, як виглядає блок «не перевірено».

## Звірка акта з еталоном, рядок за рядком

```
python -m recheck.acts demo/acts_with_defects.xlsx --reference demo/acts_reference.xlsx --spec demo/acts.json --out report_acts.md
```

Перевіряє, чи акт збігається з еталонним актом по кожному рядку й підсумку. Рядки зіставляються за номером позиції, а не за місцем у таблиці, тому інший порядок рядків чи інша розкладка стовпчиків не заважають: де який стовпчик, записано у файлі правил окремо для кожного документа.

Для кожної позиції окремо: одиниця виміру, кількість, ціна, вартість і арифметика рядка в акті (кількість × ціна з округленням до копійки). Плюс три підсумки: «Разом» акта проти суми його рядків, те саме для еталона, «Разом» акта проти «Разом» еталона.

Що ніколи не стає «зійшлось»:
- позиція є в еталоні, а в акті її немає;
- зайва позиція в акті;
- номер позиції повторюється (наприклад, рядок задвоївся після повторної спроби): «не перевірено» з номерами рядків;
- текст замість числа, порожня одиниця виміру: «не перевірено» з адресою клітинки;
- рядок із числами без номера позиції або рядок після «Разом»: окремий блок звіту.

Коди виходу ті самі: `0`, `1`, `2`, `3`. Зразок звіту: [demo/report_acts.md](demo/report_acts.md).

Демо: 12 вигаданих позицій, в акті вісім підкладених помилок. На чистому акті 63 перевірки з 63 сходяться, хоча дві позиції в ньому переставлені місцями.

| № | Помилка | Що має статися |
|---|---|---|
| A1 | Обсяг узято з сусідньої позиції | кількість і вартість позиції, «Разом» проти еталона |
| A2 | Позицію пропущено | «позиції немає в акті», «Разом» |
| A3 | Рядок задвоївся після повторної спроби | «не перевірено: номер повторюється», «Разом» |
| A4 | Ціна зі старої редакції, переставлені цифри | ціна і вартість, «Разом» |
| A5 | Одиниця виміру не та, а всі суми ті самі | лише одиниця: звірка самих сум цього не бачить |
| A6 | Кількість набрана текстом | «не перевірено» для кількості й арифметики |
| A7 | Копійку відкинуто замість округлення | вартість і арифметика рядка, «Разом» |
| A8 | Зайва позиція, якої немає в еталоні | «зайва позиція», «Разом» |

Обмеження цього режиму:
- Розкладка стовпчиків у демо умовна. Справжнього вивантаження акта з кошторисної програми автор не бачив; під реальний файл міняються літери стовпчиків і номер першого рядка у файлі правил.
- Еталон вважається правильним. Його арифметика перевіряється лише через «Разом» проти суми рядків.
- Назви робіт не звіряються, лише номери позицій. Позицію, якої немає в обох документах, звірка не побачить.
- Звірки акта з договірною ціною, попередніми актами і залишками обсягів тут ще немає.

## Як перевірено сам інструмент

Числа нижче отримано на одному ноутбуці (Windows 11, Python 3.12.6): 20.11.2026, а після додавання звірки актів перераховано 23.11.2026.

- `pytest`: 127 тестів, усі зелені (з них 33 на звірку актів).
- Тести і код писались разом, тому зелений прогін сам нічого не доводить. `python tools/mutants.py` по черзі вносить у код 51 навмисну поломку (наприклад, «текст у сумі мовчки пропускається» або «допуск розширено на копійку») і перевіряє, що тести падають. Спіймано 51 з 51 (з них 15 на звірку актів). Поломки придумував той самий автор, що й тести, тож це нижня планка, а не доказ повноти.
- Це підтвердилось одразу. Перша версія мала 15 поломок, усі спіймані, і все одно незалежне рев'ю іншим агентом знайшло п'ять дір: наприклад, рядок із чужим кодом усередині групи проходив як «зійшлось». Поломки перевіряють тести, які є, а не ті, яких бракує. Усі п'ять закрито, на кожну є тест і поломка; подробиці в журналі.
- Після публікації код прочитав ще один агент-рецензент, якому дали лише публічну сторінку. Він знайшов ще п'ять місць, де інструмент мовчав або брехав кодом виходу: зламаний файл правил давав код 1 («є розбіжності») замість 3, таблиця без жодної перевірки давала код 0, рядок із від'ємним числом у дужках зникав без зауваження, мінус «−» з власного звіту не читався назад, код «2015.002» проходив як рядок групи «201». Усе закрито того ж дня, поломок стало 32.
- Третій рецензент того ж дня запустив усе сам і додав 12 власних поломок: 5 вижили, дві з них змістовні. Він знайшов три місця, де код виходу або статус казали неправду: цифра замість літери стовпчика у правилах валила програму з кодом 1, хоча журнал уже мав правило «помилка в правилах це завжди код 3»; звіт у теку, якої немає, теж давав код 1 на чистому файлі; допуск `1e30` приймався і ховав три розбіжності з восьми в демо. Закрито, поломок стало 36. Одне його зауваження лишилось як є і записане вище: порожній доданок не змінює код виходу. Усі три рев'ю робили моделі, не люди.
- Один прогін на демо-файлі займає 0,02 с (один замір, час друкується в консолі при кожному запуску).

## Звідки метод

Метод узято з двох реальних перевірок фінансових звітів у липні 2026 року. У першій було 77 контрольних перевірок: кожен підсумок квартального звіту перераховано з деталізованих рядків. 75 зійшлись копійка в копійку, а дві розбіжності виявились помилкою в самому шаблоні звіту, де рядок «Всього» губив один доданок. У другій оборотну відомість складу розібрано до рядків: сума деталей мала дорівнювати підсумку файлу.

Ті файли і скрипти приватні. Тут метод перенесено на вигадані дані і переписано так, щоб правила перевірки жили в окремому файлі, а не в коді. Старий скрипт мав ваду, якої тут уже немає: текст у клітинці він рахував як нуль. Цим інструментом ті 77 перевірок заново не проганялись.

## Чого тут немає

- Читає лише `.xlsx`. Старий `.xls` треба спершу перезберегти.
- Основний режим звіряє підсумки всередині одного файлу і між його аркушами. Порядкова звірка двох документів є лише для пари «акт проти еталонного акта», обмеження в її розділі.
- Правила пише людина. Інструмент не здогадується, які клітинки є підсумками.
- Об'єднані клітинки читаються як порожні. Формула, яку Excel не перерахував перед збереженням, дає «не перевірено».
- Числа беруться з точністю 15 значущих цифр, щоб двійковий хвіст на кшталт 0,30000000000000004 не ставав розбіжністю. На файлі, збереженому справжнім Excel, це не перевірено: демо-файли пише бібліотека.
- Належність рядка до групи перевіряється за правилом «код рядка починається з коду групи, далі йде роздільник». Для таблиць з іншою схемою кодів правило треба буде розширити.
- Дублі кодів не шукає: два рядки з однаковим кодом усередині групи пройдуть, якщо суми сходяться.
- «Поза перевірками» рахує числа, яких не торкнулась жодна перевірка. Число, що входить лише в перевірку зі статусом «не перевірено», сюди не потрапляє: воно видно в блоці невиконаних перевірок.
- Перевіряється арифметика і цілісність звіту, а не зміст. Якщо сума порахована правильно з неправильних первинних даних, інструмент цього не побачить.
- Кількості в різних одиницях (штуки, літри, упаковки) не сумуються і не перевіряються.
- Скільки часу це економить порівняно з ручною звіркою, не заміряно: для цього треба засікти, скільки та сама звірка займає в людини.
